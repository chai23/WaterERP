# WaterERP Windows 列印助手開發規劃

狀態：規劃，尚未實作。日期：2026-11-17。

## 目標與預設範圍

先支援一個 Windows 列印站、兩台已安裝 Windows 驅動程式的印表機。ERP 照常在瀏覽器操作，按列印後依文件種類派送，不需每次選機或確認。可擴充多工作站；跨站派送必須明確指定，不能任意挑選在線電腦。

| 文件設定檔 | 印表機 | 預設紙張 | 行為 |
| --- | --- | --- | --- |
| 訂單套印 | 點陣機 | 240 × 127 mm，100% | 沿用現有欄位座標、字型、條碼及顯示開關 |
| 一般報表 | 雷射機 | A4 直式 | 報表版型決定分頁、頁邊界、重複表頭 |
| 寬版報表 | 雷射機 | A4 橫式 | 可獨立設定單雙面、份數、紙匣，依驅動支援 |

不更改 Windows 預設印表機，不開啟瀏覽器全域靜默列印。保留「預覽／手動列印」入口；自動派送狀態不明時禁止直接自動改走手動列印，以免重複。

## 架構決策

瀏覽器 → ERP API 列印工作佇列 → 已配對的 Windows 列印助手 → 指定 Windows 印表機。

助手主動向 ERP 取件並回報，不由網頁連接本機 HTTP 埠。第一版用短輪詢，之後可加長輪詢或 WebSocket。正式部署使用 HTTPS；現有 HTTP 區網環境須在開發部署階段一併規劃憑證與連線方式。

助手採 C#、受支援的 .NET LTS、WinForms 系統匣與 WebView2。以登入使用者的桌面程序運行，登入後自動啟動，非需要管理員權限的 Windows Service。現有 WaterErpLauncher 是伺服器維護工具，列印助手獨立發佈，讓開單電腦只需安裝列印元件。

WebView2 PrintAsync 可不顯示對話框並指定 PrinterName、紙張等參數；先以現有 HTML 版型做實機驗證。驅動對自訂紙張、邊界、紙匣與雙面的支援不一，不能只依 API 成功判定對位正確。若點陣速度或頁長不合格，再評估針對訂單的原生繪圖輸出；RAW/ESC/P 不納入第一版。

## 使用介面

- 首次安裝：配對 ERP、設定列印站名稱、選擇點陣機和雷射機、各印測試頁。
- ERP 列印設定：文件種類對應印表機設定檔、指定工作站、站點連線狀態。
- 列印操作：按下後提示已排隊／已送至印表機；正常列印不跳確認視窗。
- 工作紀錄：文件名稱、訂單號、工作站、送出人、時間、份數、狀態、錯誤與補印原因。
- 助手系統匣：連線狀態、暫停接單、開啟佇列、測試列印、設定與版本。
- 助手離線：提示目標站離線，工作保留待處理；過期工作暫停，不在隔天自動大量出紙。

## 版面與列印內容

沿用 buildOrderSlipHtml 的輸出與現有拖曳編輯器。建立工作時將目前已選用版面與列印資料製成不可變快照，包含紙張、版本、樣式和條碼，避免排隊後改訂單或改版面造成內容變動。

現有版面儲存在瀏覽器 localStorage：第一版送出工作必須攜帶該次版面快照；第二階段再新增伺服器版面設定檔及匯入既有 JSON。預覽輔助格線和拖曳樣式不加入列印工作。

後端驗證文件讀取及列印權限。使用受控版型或經限制的無腳本 HTML、內嵌樣式與資源，禁止助手執行任意腳本、存取外部網址或本機檔案；限制份數、頁數與內容大小。助手不用管理員權限，配對憑證可撤銷且只允許讀取指派本站的工作。

## 佇列及重複列印處理

建議狀態：queued、claimed、rendering、submitted、failed、unknown、cancelled、expired。

- 建立工作帶 idempotencyKey，同次按鈕操作與網路重試共用識別碼；刻意補印產生新工作並連結原工作。
- 後端原子領取與租約避免多助手同時取件；每台印表機依序提交。第一版可先單一渲染器序列處理。
- 助手持久保存收件與提交紀錄。送印前明確失敗可重試；送印後斷線或當機造成結果不明則標記 unknown，須人工核對後補印。
- 不宣稱端到端 exactly-once：Windows 佇列成功不等於紙已實際印出。介面使用「已送至印表機」，實際紙盡、卡紙等狀態依驅動能提供的資訊顯示。
- 未提交工作可取消；已進 Windows 佇列後只能嘗試取消，不能保證紙張未印出。
- 離線保留時間與逾時規則可設定，過期預設暫停並提示人工處理。
- 記錄保留業務識別與結果，完整列印內容採限期保存、限權存取及清除策略。

## 建議程式及資料結構

- tools/WaterErpPrintAgent：獨立桌面助手、設定與安裝封裝。
- apps/api/src/modules/printing：工作站配對、設定檔、工作排隊、領取及狀態回報。
- apps/web-admin/src/printing：統一送印入口、狀態顯示及手動列印備援。
- 新資料表：print_stations、print_profiles、print_jobs、print_job_events。
- API 概念：建立／讀取／取消列印工作；助手註冊與心跳；原子領取；工作狀態回報。正式路由和 schema 在實作時依既有 API 慣例定義。

## 開發階段與驗收

1. 實機可行性驗證：指定兩台印表機直接列印；點陣連印至少 20 張，確認首張對位、頁長無累積漂移、中文字型與條碼；雷射測 A4 直橫式及多頁分頁。未通過前不承諾輸出引擎。
2. 最小可用版：助手安裝與登入自啟、單站配對、兩種印表機設定檔、訂單送印、至少一份代表性報表、簡易狀態與人工補印。
3. 可靠性：持久佇列、冪等、斷線與重啟恢復、結果不明人工確認、取消與過期、配對撤銷、權限與記錄。
4. 推廣：多工作站、其餘報表串接、批次訂單、集中版面管理、更新與回復流程。

驗收需涵蓋：不顯示列印對話框、不依賴 Windows 預設機、目標機離線不轉送其他機、快速重按不意外重複、不同文件正確分流、補印可追蹤、送印前後中斷分別處理、報表跨頁無截斷。不得以模擬列印取代實體連續紙驗收。
