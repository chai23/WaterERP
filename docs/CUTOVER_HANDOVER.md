# 上線交接

入口：主檔資料 → 上線交接（原切換日開帳）。管理員及會計可使用。

## 四步驟

1. 設定新系統啟用日，截止日固定為前一日。建議在月結邊界切換，舊系統先結帳，不必等到收款。
2. 建立並儲存交接草稿。逐戶核對金額預收（沒有也要填 0）、預付桶、各地址空桶，以及每筆舊單的交接方式。
   每頁 100 位，支援搜尋與待確認篩選。沒有待處理舊單、沒有異常的客戶，可在確認沒有金額預收後批次核對本頁，保留各戶桶數。
3. 分別核對一般欠款、月結已出帳未收、月結尚未出帳、預收、預付桶及空桶。下載 CSV 留存。每戶異常、排除或調整必須記錄原因／後續處理方式。
4. 確認來源凍結與總額，儲存並檢查通過後正式啟用。所有寫入在同一資料庫交易內；失敗全部回復，成功後鎖定，重複啟用不會再開帳。

## 日期與資料來源

舊庫必須為截止日營業結束的凍結資料或備份。舊系統的現金「已收」旗標及客戶桶數沒有完整歷史版本，不能只輸入過去的日期就還原當天餘額。

- 訂單範圍為啟用日前（含截止日最後一秒）；收款以收款日判斷。
- 截止日後的收款會阻擋啟用。缺少收款日期的款項不會被悄悄扣掉，必須人工核對。
- 草稿保留來源快照與新庫狀態雜湊。來源、主檔或交易變動後必須重新產生草稿，不會用新數字悄悄替換已核對內容。
- 舊庫讀取在一致性交易內完成；正式交接期間仍需停止舊系統寫入。
- 金額預收沒有可確認的舊庫統一來源，採明確人工輸入。預收類型訂單不代表有等額預收錢包。

## 各類帳務處理

| 類型 | 行為 |
| --- | --- |
| 一般未收款 | 剩餘金額建立 opening_balance 應收，保存舊單到 AR 單號的對照及到期日。 |
| 月結已出帳未收 | 建立月結期初應收，可收款沖帳，並出現在月結對帳清單。 |
| 月結尚未出帳 | 建立獨立待結項目，第一次開立相符稅額口徑的月結時才產生 AR。舊單號保留於月結來源紀錄。 |
| 待結月結稅額口徑 | 不開發票／含稅／未稅外加稅。不同口徑分批開立，不重算已出帳期初的稅。 |
| 已部分收款的未結月結 | 須先在舊系統完成結帳，以「月結已出帳未收」承接剩餘金額，避免收款與稅基不明。 |
| 金額預收 | 建立預收錢包期初與流水；交接時不自動抵扣其他欠款。 |
| 預付桶 | 保存核對後期初及流水，不與金額預收混用。 |
| 空桶 | 逐配送地址核對與保存；多地址不會只寫入預設地址。 |
| 未完成配送 | 預設排除應收，必須記錄待辦移交方式；已付款但未配送者仍出現在交接表。 |

一戶可有多種帳務類型。不要把欠款減預收後只存一個淨額。

## 防止覆寫及補正

- 已有新系統交易、預付商品餘額或金額錢包的客戶不得用期初覆蓋，須排除並另行對帳。
- 已做過舊版開帳的環境會阻擋重複交接，需先核對既有帳務；不自動刪除或沖掉既有應收。
- 尚未啟用的草稿可重新產生；會清除人工編輯並重新核對。
- 已啟用後不提供重新同步／重新覆寫功能。後續差異使用既有收款、折讓及帳務調整流程並保留紀錄；不能刪除交接鎖來重跑。
- 單一安裝只有一個正式交接批次。客戶被排除時須完成後續處理安排，不能在啟用後偷偷追加到同一批。
- 舊版 preview/apply/sync-balances API 已停用，回傳 410。
