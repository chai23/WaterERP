# 超好企業進銷存系統：現金往來、司機收款與櫃台沖帳 — 使用教學

本教學說明 **現金客戶** 在「部分收款、跨趟結清」情境下，**後台開單**、**司機配送**、**辦公室核銷**、**櫃台對帳** 的建議流程。技術規則摘要見 [`BILLING.md`](./BILLING.md)。

---

## 一、名詞與「唯一真相」

| 名詞 | 說明 |
|------|------|
| **訂單總額** | 本張訂單商品金額合計（本單應收貨款）。 |
| **可催收舊欠** | 同客戶其他已可催收之未清 **AR**（不含尚在配送途中、未回報之他單）。 |
| **建議收款總額（本趟應收現金）** | **本單未清 AR** ＋ **可催收舊欠** − **預收錢包**。司機依此收款。月結份額通常不列入當場應收。 |
| **客戶往來餘額** | `Σ(有效 AR outstanding) − 預收錢包`（見帳務摘要 `accountBalance`）。 |
| **實收（司機填寫）** | 司機現場收到的現金／支票。 |
| **差額** | `實收 − 建議收款總額`（核銷清單與司機回報分類用）。 |

**原則**：現金應收以 **AR** 為唯一來源。開單／確認配送量時立 AR；核銷或 AR 作業台收款時建立收款單並沖帳（**本單優先**，再依到期日沖舊欠）。溢收進預收錢包。

---

## 二、客戶主檔：三種結帳方式

在 **資料庫 → 客戶資料** 設定：

1. **現金**：當場收款為主；跨趟欠款併入「建議收款總額」，核銷時本單優先沖 AR。  
2. **月結**：司機端通常不將月結貨款列為本趟應收現金；應收於對帳批次立帳後，於 AR 作業台收款。  
3. **預付（桶）**：送達時依「預付扣桶」商品與明細扣桶數。**補桶數（儲值）**請在 **新增訂單** 加勾「預付桶儲值」之明細（現金列）；**儲值桶數**須等本單**現金 AR 全數沖清**後才入預付桶餘額。

下單時會**快照**當時的結帳方式到訂單，避免日後改客戶主檔影響舊單解讀。

---

## 三、後台：開立訂單（現金客戶）

1. **新增訂單** → 選客戶、地址、商品。  
2. 畫面會顯示 **客戶帳務提示**（結帳方式、往來餘額、預付桶餘額等）。  
3. **無須**再填「本趟加收」：舊欠與本單由系統合併為司機端「建議收款總額」。  
4. 送出後訂單成立並立現金 AR；請提醒司機以 **建議收款總額** 為準。

---

## 四、司機端：配送與收款

1. 開啟 **超好企業進銷存系統 · 司機任務**（`web-driver`），選擇員編與**配送日**（須與後台分派日一致）。  
2. **現金客戶**每一筆任務會顯示：  
   - **前期未收／可催收舊欠**  
   - **本次送貨訂單金額**  
   - **建議收款總額**（請依此向客戶收款）  
   - **客戶往來餘額**  
   - **上一筆已結案配送**（同客戶）  
3. 送達後填 **空桶回收**、**現場收款**（理想上等於建議收款總額）。  
4. 提交後狀態為 **待辦公室核銷**；訂單尚未完成、庫存尚未扣減，直到辦公室確認。

---

## 五、辦公室：核銷訂單

1. 進入 **訂單資料 → 核銷訂單**。  
2. 清單之 **應收現金**／**差額** 依建議收款口徑顯示。  
3. 核銷 **確認** 後：訂單完成、出庫；有實收則入收款單並沖 AR（本單優先）；溢收轉預收錢包。  
4. 若與司機回報有爭議，應先釐清再核銷。

---

## 六、櫃台／辦公室：沖帳與對帳怎麼做才「正確」

### 1. 釐清錢從哪裡來

| 情境 | 建議處理 |
|------|----------|
| 錢是 **司機帶回** 的 | 以 **核銷** 為準：實收已寫入收款單並沖 AR。 |
| 客戶 **匯款／櫃台補繳** | 使用 **AR 作業台 → 收款沖帳**，填實際匯款日與金額；系統依到期日 FIFO 沖未清 AR。 |

### 2. 避免重複入帳

- 核銷已產生收款單時，**不要**再在 AR 作業台把同一筆司機實收記一次。  

### 3. 月結／預付

- 月結：於 **AR 作業台／月結批次** 立帳後收款；短收不會整批標已付。  
- 預付：送達扣桶為主；「預付桶儲值」為現金 AR，桶數入帳以本單現金 AR 是否沖清為準。

---

## 七、常見情境範例（現金客戶）

**情境 A：第一趟應收 60、實收 0 → 短收 60**  
- 核銷後 AR 未清 **60**（本單已立帳，無收款沖銷）。

**情境 B：第二趟訂單總額 180，要把上一趟少收的 60 一併收回**  
- 開單：建立 180 元訂單。  
- 司機畫面：舊欠 60＋本次 180＝建議收款 240。  
- 司機填實收 240；核銷後本單優先沖本單，再沖舊欠（或依可催收規則），AR 清為 0。

**情境 C：建議收款 240，客戶只付 200**  
- 司機填實收 200 → 少收；沖完可沖部分後，剩餘欠款反映在 AR。

**情境 D：無前期欠款，本單 100、客戶付 100**  
- 建議收款 100；足額。

## 八、與司機端 API 的對應（給維護者）

`GET /api/driver/today` 回傳的每一筆任務會多帶 **`driverBillingHints`**，包含：  
`billingType`、`orderTotal`、`cashPriorBalance`（可催收舊欠）、`cashDue`（建議收款總額）、`orderCashAdjustment`（舊欄位，固定 0）、`accountBalance`、`prepaidBarrelBalance`、`lastCompletedDelivery`。
