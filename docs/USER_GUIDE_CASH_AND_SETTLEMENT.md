# 超好企業進銷存系統：現金往來、司機收款與櫃台沖帳 — 使用教學

本教學說明 **現金客戶** 在「部分收款、跨趟結清」情境下，**後台開單**、**司機配送**、**辦公室核銷**、**櫃台對帳** 的建議流程。技術規則摘要見 [`BILLING.md`](./BILLING.md)。

---

## 一、名詞與「唯一真相」

| 名詞 | 說明 |
|------|------|
| **訂單總額** | 本張訂單商品金額合計（本單應收貨款）。 |
| **前期未清現金欠款** | 依客戶流水帳中「現金應收相關」分錄加總（見 `BILLING.md` §6）；**正**＝仍欠公司。 |
| **建議收款總額（本趟應收現金）** | **僅現金客戶**：前期未清現金欠款 ＋ 本張訂單總額。司機依此收款。**月結客戶**：司機端**本趟應收現金為 0**（不列入當場應收；貨款以辦公室核銷後月結對帳為準）。 |
| **客戶往來餘額（全帳）** | 客戶流水帳 **全部**分錄加總（含月結等）；司機畫面註明為「全帳」供參考。 |
| **實收（司機填寫）** | 司機現場收到客戶的現金。 |
| **差額** | `實收 − 建議收款總額`（核銷清單與司機回報分類用）。 |

**原則**：核銷時系統先為**本單立帳**（應收），再將實收依 **FIFO**（先沖最舊訂單之未清應收）沖銷，與常見 ERP「應收／收款分離」一致。

---

## 二、客戶主檔：三種結帳方式

在 **資料庫 → 客戶資料** 設定：

1. **現金**：當場收款為主；跨趟欠款由系統自動合併於「建議收款總額」，核銷時 FIFO 沖帳。  
2. **月結**：司機端**不**將訂單金額列為本趟應收現金（顯示為 0）；應收在辦公室核銷後入帳，並於月結對帳頁處理收款。  
3. **預付（桶）**：送達時依「預付扣桶」商品與明細扣桶數。**補桶數（儲值）**請在 **新增訂單** 加勾「預付桶儲值」之明細（現金列）；核銷後與一般現金貨款一樣會**立帳／欠款**（司機未收足亦可核銷）。**儲值桶數**須等本單**現金應收在帳上全數沖清**後（現場收款、匯款沖帳、預收扣抵等），才會加進預付桶餘額；客戶訂單列表會顯示「儲值待入帳 N 桶」。

下單時會**快照**當時的結帳方式到訂單，避免日後改客戶主檔影響舊單解讀。

---

## 三、後台：開立訂單（現金客戶）

1. **新增訂單** → 選客戶、地址、商品。  
2. 畫面會顯示 **客戶帳務提示**（結帳方式、往來餘額、預付桶餘額等）。  
3. **無須**再填「本趟加收」：前期欠款與本單貨款由系統自動合併為司機端之「建議收款總額」。  
4. 送出後訂單成立；請提醒司機以 **建議收款總額** 為準（司機端會顯示前期、本次、合計）。

---

## 四、司機端：配送與收款

1. 開啟 **超好企業進銷存系統 · 司機任務**（`web-driver`），選擇員編與**配送日**（須與後台分派日一致）。  
2. **現金客戶**每一筆任務會顯示：  
   - **前期未收現金欠款**  
   - **本次送貨訂單金額**  
   - **建議收款總額**（前期＋本次；請依此向客戶收款）  
   - **客戶往來餘額（全帳）**  
   - **上一筆已結案配送**（同客戶）：上一筆單號、應收、實收、差額 — 方便了解上次狀況。  
   **月結客戶**會顯示訂單總額供參考，但**本趟應收現金為 0**（不強制當場收貨款；與月結對帳收款分開）。  
3. 送達後填 **空桶回收**、**現場收款**（現金客戶理想上應等於建議收款總額；月結客戶可填 0 或客戶臨時交付之現金，照實填寫）。  
4. 提交後狀態為 **待辦公室核銷**；訂單尚未完成、庫存尚未扣減，直到辦公室確認。

---

## 五、辦公室：核銷訂單

1. 進入 **訂單資料 → 核銷訂單**。  
2. 清單之 **應收現金**／**差額**：**現金客戶**為前期現金欠款＋本單訂單總額，差額＝實收−應收；**月結客戶**司機回報之應收為 0，若仍顯示差額多為司機填寫之臨時現金。  
3. 核銷 **確認** 後：訂單完成、出庫；現金客戶為本單 **立帳** 並將實收 **FIFO 沖銷** 最舊未清應收；若實收仍有剩餘則為多收。  
4. 若與司機回報有爭議，應先釐清再核銷。

---

## 六、櫃台／辦公室：沖帳與對帳怎麼做才「正確」

### 1. 釐清錢從哪裡來

| 情境 | 建議處理 |
|------|----------|
| 錢是 **司機帶回** 的 | 以 **核銷** 為準：實收、差額已由司機回報與辦公室確認寫入；沖帳由 FIFO 完成。 |
| 客戶 **來櫃台補繳**（未經司機） | 應有 **手動收款／調帳** 機制（若尚未建專用畫面，可於後續擴充）；並在備註註明原因，避免與司機實收重複。 |

### 2. 避免重複入帳

- 核銷已產生立帳與沖銷流水時，**不要**再在別處把同一筆差額記一次。  

### 3. 月結／預付

- 月結：當場收款不強制等於訂單總額；於 **月結對帳** 頁選 **結帳截止日** 與客戶，系統列出待結清訂單並可 **分次／多方式** 入帳；沖銷依訂單 **FIFO**（核銷時間早者先沖），短收不會整批標已付。  
- 預付：送達扣桶為主；若有「預付桶儲值」明細，該部分為 **現金應收**，司機端會併入建議收款；**桶數入帳**則以本單現金應收是否沖清為準（見上文）。

## 七、常見情境範例（現金客戶）

**情境 A：第一趟應收 60、實收 0 → 短收 60**  
- 核銷後往來 **+60**（本單立帳，無沖銷）。

**情境 B：第二趟訂單總額 180，要把上一趟少收的 60 一併收回**  
- 開單：**僅**建立 180 元訂單即可。  
- 司機畫面：**前期未收 60**＋**本次 180**＝**建議收款 240**。  
- 司機填實收 **240**；核銷後 FIFO 先沖第一趟 60、再沖第二趟 180，往來 **0**。

**情境 C：建議收款 240，客戶只付 200**  
- 司機填實收 200 → 少收；FIFO 沖完可沖部分後，剩餘欠款反映在往來。

**情境 D：無前期欠款，本單 100、客戶付 100**  
- 建議收款 100；足額。

## 八、與司機端 API 的對應（給維護者）

`GET /api/driver/today` 回傳的每一筆任務會多帶 **`driverBillingHints`**，包含：  
`billingType`、`orderTotal`、`cashPriorBalance`（前期未清現金欠款）、`cashDue`（建議收款總額）、`orderCashAdjustment`（舊欄位，固定 0）、`accountBalance`、`prepaidBarrelBalance`、`lastCompletedDelivery`。
